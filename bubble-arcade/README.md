# 泡泡堂 · BUBBLE ARCADE

经典《泡泡堂 / Crazy Arcade》的 H5 复刻：15×13 棋盘，放泡泡、水柱十字爆破、炸箱吃道具、困泡自救与队友救援，1–2 人本地对战 + AI。**PC 键盘 + 手机触屏**双操作，单文件零外部资源。

**在线游玩**：<https://case.youyongai.com/bubble-arcade/>

## 玩法

- **键盘**：P1 `WASD` + `Space`；P2 `↑←↓→` + `Enter`；`Esc`/`P` 暂停，`M` 静音。
- **触屏**：左半屏按住滑动移动（按下处即摇杆原点，左下角常驻底座提示；4 向吸附 + 轴间迟滞防抖 + 快速划动立刻换向，死区内原地站定）；右下大按钮放泡（右上角实时显示还能放几个泡；被困时按钮变脉冲提示连点自救，摇杆来回变向同样计入）；右上角暂停。竖屏棋盘居上、横屏棋盘居中，控制区自动避让 + 安全区适配；`?touch=1` 桌面强制开启调试，`?touch=0` 关闭。详见下节「手机端专项优化」。
- **泡泡**：脚下放泡，2.4 秒后十字水柱炸开（可调 1.4–3.2s）。遇硬墙停止，炸掉软箱后停止，碰到其它泡泡链式引爆。
- **困泡**：被水柱命中不会立刻死，而是被裹进泡泡 3.6 秒。期间狂按方向键/放泡键可提前挣脱（约 11 下）；队友贴身站住即可救援。倒计时结束泡泡破裂淘汰；困泡状态再被**别人**的水柱打中立即淘汰（自家水柱不误伤）。
- **戳泡**：走过去碰到敌人的困泡会把它戳破（0.16 秒延迟），敌人直接淘汰——不用等水柱，也不用等倒计时。
- **道具（10 种）**：
  - 基础：**泡泡+1**（上限 8）· **威力+1**（上限 8）· **速度+1**（上限 6.2 格/s）· **踢靴**（走向泡泡把它踢出去，撞到玩家直接困住）· **护盾**（抵挡一次水柱 + 1.3s 无敌）
  - 稀有（金边）：**银针**（自动抵消一次困泡）· **泡泡靴**（可以直接穿过泡泡）· **钻头**（水柱穿透软箱并多延伸 1 格）· **磁铁**（自动吸取 4.2 格内的道具）· **手套**（走向泡泡把它举起来，再按放泡键向前扔 3 格）
  - 软箱按权重掉落（基础道具常见、稀有能力道具较少），地上道具会被水柱冲毁。
- **模式**：混战（2/3/4 人，各自为战）· 2v2 组队（队友同色，需贴身互救）。
- **赛制**：先到 N 胜（1/2/3/5）赢下比赛；每局 150 秒，超时进入**死亡模式**随机落泡直到分出胜负。
- **5 张地图**：青草庭院 / 对角竞技场 / 十字要塞 / 双子柱厅 / 霓虹迷阵，四角出生点保护 + 中心对称软箱布局。
- **3 档 AI**（重写于 v2，见下）：简单（反应慢、少自救、放泡少）/ 普通 / 困难（快速自救、预判堵人、主动开图）。AI 会算引信、算步数、算你下一步往哪走，不再往自己脚下丢泡等死。
- **战绩**：比赛场次 / 胜场 / 胜率 / 局数 / 放泡 / 炸箱 / 道具 / 救援 / 连胜，`localStorage` 持久化。

## AI v2：时间感知的"会算账"机器人

老版 AI 的致命伤是**只算空间不算时间**——它只看"哪格会被炸"，找到最近的安全格就冲，但算不出"2.4 秒后爆，我根本跑不过去"；找不到安全格时就**站着等死**。实测 24 局 4 AI 对战，**69% 的死亡是自己炸的**，AI 平均只活 10.6 秒。

v2 把 AI 从"反应式"改成"算账式"：

| 能力 | 做法 |
|---|---|
| **时间感知危险图** | 每格记录"还有几秒会被炸"（0 = 永远安全），并模拟链式引爆（被别的泡泡点燃 → 0.09s 后二次爆炸，炸点范围更大） |
| **时间感知逃生** | 搜索时约束"走到下一格并穿出它的时刻必须早于它被炸"，留 0.2s 安全余量；没有全安全路线时退化为"跑向最晚爆炸的区域"（活得最久），而不是站着不动 |
| **不钻死角** | 逃生路线优先走非死胡同格——死胡同被人堵一个口就彻底没救 |
| **区域安全分析** | 连通区域大小，AI 知道自己是不是困在死胡同里，会主动炸开通往大区域的路 |
| **预判型放泡** | 记忆对手的移动方向，只有"连续 0.45s 朝同一方向移动"才敢预判；另有两种高确定性杀法：**走廊封路**（敌人在走廊尽头，一泡封死必杀）与**迎面堵人**（敌人正冲我来，往脚下放一泡） |
| **躲闪分析** | 放泡前算敌人还剩几条退路：无退路 → 必杀；有 1 条 → 半稳；多退路 → 放弃（不再浪费泡泡） |
| **走位对齐** | 与自由移动手感对齐：先把身体对齐到通道中线再转向，不会卡墙角；卡住检测在所有模式下生效 |
| **快速自救** | 困泡后高速连按（11 下）脱困，简单档故意放弃 |
| **确定性随机** | 每个 bot 一条种子随机流，同一局可完整重放，方便回归对比 |

**效果（24 局 × 4 AI，同种子可复现）**

| 指标 | v1（旧 AI） | v2（新 AI） |
|---|---|---|
| 自炸致死 | 69% | **0%** |
| 被自己的泡泡困住 | 0.96 次/人局 | **0.41 次/人局**（-57%） |
| 平均存活 | 10.6s | **57.9s**（5.5 倍） |
| 平均死亡时间 | 27.5s | **50.9s** |
| 人均放泡 | 9.1 | 29.4（从躲着不打变成会主动开图） |

**5 张地图全部 0% 自炸**（普通档，各 12 局平均存活）：青草庭院 64.2s · 对角竞技场 52.4s · 十字要塞 72.8s · 双子柱厅 48.1s · 霓虹迷阵 59.0s。

**难度梯度**（威胁度 = 放着不动的真人被 AI 打死，24 局）：

| 难度 | 自炸致死 | 平均存活 | 人均放泡 | 威胁度 |
|---|---|---|---|---|
| 简单 | 0% | 50.6s | 19.2 | 7/12 局，平均 129.1s |
| 普通 | 0% | 57.9s | 29.4 | 7/12 局，平均 133.1s |
| 困难 | 0% | 89.4s | 43.9 | **10/12 局，最快 9.2s** |

## 手机端专项优化

老版手机端"不爽"的根因**不是操作，是整套 UI 被棋盘的缩放一起压扁了**。iPhone 14（390×844）上棋盘缩到 38.6%，于是标题只有 **6.2px**、玩家名 **4.6px**、计时器 10px——根本读不了；竖屏时棋盘上方空着 168.7px、下方 355px 全是废空间。

| 痛点 | 做法 |
|---|---|
| **UI 读不清** | 文字层（标题/设置/结算/HUD/倒计时/提示条）整体搬出被 `transform` 缩放的 `stage`，改用视口坐标独立渲染——`stage` 有 transform，里面的 `fixed` 元素也会跟着缩，只能搬出去 |
| **竖屏全是废空间** | 棋盘顶到屏幕上方（顶部留 HUD 条），下方整块让给拇指操作区；可用面积占比从 30% 提到 39% |
| **不知道往哪跑** | 脚下画引信倒计时环 + 标出可逃方向箭头（复用 AI v2 的爆炸范围计算，桌面端不画） |
| **摇杆转向肉** | 死区 12→8px；轴间迟滞 1.35/10px → 1.15/6px；新增**快速划动**——拇指划动角度突变超 49° 立刻换向，不等迟滞（迟滞刚好挡住的恰是 45°~49° 这段） |
| **找不到摇杆** | 左下角**常驻**摇杆底座 +「拖动移动」标签，按下时高亮（原设计只有一次性落点提示圈，滑完就消失） |
| **不知道还能放几个泡** | 炸弹键右上角实时角标显示剩余可放数，放完置灰 |
| **被困不知道能自救** | 被困时炸弹键变橙色脉冲呼吸圈，提示连点脱困 |
| **手上没反馈** | 放泡 / 爆炸 / 被困 / 脱困 / 拾取 / 淘汰 / 胜负给振动反馈（`navigator.vibrate`，iOS 不支持自动降级为无声） |
| **手机上卡** | 渲染 DPR 上限 2 → 1.5（像素量少 44%）；竖屏给横屏引导（横屏一格 28.8px vs 竖屏 25.3px） |

**手机端实测（iPhone 14 视口 390×844）**

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 标题字号 | 6.2px | **44px** |
| 玩家名字号 | 4.6px | **11px** |
| 计时器字号 | 10.0px | **19px** |
| 棋盘上方废空间 | 168.7px | **46px**（HUD 条） |
| 棋盘可用面积占比 | 30% | **39%** |
| 炸弹键 | 86px | **96px** + 剩余数角标 |
| 摇杆提示 | 一次性落点圈 | **常驻 108px 底座** |

**桌面端零影响**：移动端增强层整体挂在 `BA.MOBILE.enabled` 开关下——桌面不创建 UI 层、不改任何 DOM 归属、不改任何字号、不生成触摸控件；`test/mobile-ego.mjs` 里有 6 条断言专门守这条线。

## 技术要点

- **单文件**：`src/*.js` 模块化开发 → `build.py` 内联进 `index.html`（约 243 KB，零外部图片/字体/音频）。
- **全程序化美术**：`art.js` 用离屏 Canvas 2× 预渲染地板/硬墙/软箱/4 角色 ×4 朝向 ×4 帧/困泡/5 道具/8 帧泡泡/头像，五套主题配色，运行时缩放绘制，高分屏清晰。
- **全合成音效**：`audio.js` WebAudio 21 个 cue（放泡/爆炸/链式/炸箱/吃道具/被困/救援/淘汰/倒计时/胜负）+ 112 BPM 8bit BGM，`unlock()` 幂等、循环干净、`visibilitychange` 停 BGM、`duck()` 压背景。
- **粒子特效**：`fx.js` Canvas2D 对象池（上限 620），径向渐变 + `lighter` 叠色，禁 `shadowBlur`；金币/水花/彩带/浮字/震屏，DPR ≤ 2。
- **物理与手感**：120 Hz 固定步长 + **自由移动**（可在格子内任意位置行走，不再吸附行/列中线）；只在真正被挡住时自动对格绕过箱角，既保留自由手感又不会卡死在格子缝里。放泡者离开格子前可自由穿过自己的泡泡、踢泡直线滑行撞人困泡。**身体已压住的泡泡不再阻挡移动**——否则自由移动下身体常横跨两格，敌人把泡泡丢到旁边就会把人永久冻死（实测这是老 AI 头号死因）。
- **渲染**：静态层（地板/硬墙）预渲染到离屏 Canvas，每帧只重绘软箱/道具/泡泡/水柱/角色；`rAF` + `setInterval` 双驱动防后台节流冻结，实测 120 FPS。
- **AI**：见上节「AI v2」——时间感知危险图（含链式引爆）+ 时间感知逃生寻路 + 区域安全分析 + 预判型放泡 + 确定性随机流，26 Hz 决策节流。
- **输入缓冲**：按键按下后至少保持 90ms，重复 keydown 事件会补一次状态同步——掉帧或浏览器丢事件时不会整段输入失效（真人手感也更跟手）；自救冷却改用游戏时钟，与帧率无关。
- **触屏操作**：`touch.js` 动态虚拟摇杆 + 放泡/暂停键，纯 DOM 多点触控（touch identifier 跟踪，摇杆/放泡互不干扰），输入桥接复用键盘的 `dirStack`/`bombPressed`/`mashEscape` 原语，键盘逻辑零改动；被困时摇杆变向计入自救；放泡采用「按下置位、游戏消费清除」防快速点按丢拍。摇杆手感：死区 8px、轴间迟滞 1.15/6px、快速划动（角突变 > 49°）立刻换向。
- **移动端增强层**：`mobile.js` 独立模块，只在触屏模式启用——把文字 UI 迁出被缩放的 `stage`（新建 `#uiLayer` 承载 HUD/倒计时/提示条/菜单屏）、按 `env(safe-area-inset-*)` 重排竖屏/横屏布局、渲染 DPR 降到 1.5、振动反馈、炸弹键剩余数角标、横屏引导。桌面端 `BA.MOBILE.enabled` 恒为 false，整层逻辑一行不执行。
- **危机提示**：`game.js` 抽出 `blastCellsOf(b, pure)` 统一计算爆炸覆盖格（`explodeBomb` 与提示查询共用，纯查询模式不触发链式点燃副作用），触屏模式下在真人脚下画引信倒计时环 + 可逃方向箭头；`__ba.threatInfo()` 可查。
- **测试钩子**：`window.__ba` 暴露 `state / phase / players / board / cfg / fps / errors`、`start / fastForward / winNow / teleport / give / placeBomb / trap / forceEnd / setSpeed`、`held(id) / bombAt(x,y) / itemCount / dropItemAt(x,y,type) / dropItems(n,type)`、`touch.dir / touch.bomb`（触屏桥状态）；URL 参数 `?auto=1`（机器人演示）、`?reset=1`（清档）、`?muted=1`、`?fps=1`、`?map=`、`?speed=`、`?touch=1|0`。

## 开发

```sh
python3 build.py                 # src/ → index.html 单文件
python3 test/serve.py 8771       # 本地预览 http://127.0.0.1:8771
ego-browser nodejs < test/logic-test.mjs   # 逻辑回归（自由移动 / 戳泡 / 10 种道具，33 项）
ego-browser nodejs < test/touch-ego.mjs    # 触屏回归（摇杆 / 迟滞 / 放泡 / 自救 / 暂停，25 项）
ego-browser nodejs < test/mobile-ego.mjs   # 手机端回归（手机视口布局 / 可读性 / 桌面零影响，26 项）
```

**AI 仿真器**（量化 AI 强弱，AI 调参专用）：

```sh
echo '{"rounds":24,"diff":"normal","map":"garden"}' > /tmp/ba-ai-cfg.json
ego-browser nodejs < test/ai-sim.mjs    # 全 AI 对局，统计死因分布
```

输出：各死因占比（自炸 / 被炸 / 被自己泡泡困住）、自炸率、被困次数、存活时长、放泡 / 炸箱 / 击杀数，以及"威胁度"（不操作的真人被 AI 打死几局）。`diff` 可选 `easy|normal|hard`，`map` 可选 `garden|arena|cross|pillars|maze`。
> ego-browser 不继承 shell 环境变量，配置必须写进 `/tmp/ba-ai-cfg.json`。

**真人视角验证**（1 人 + 3 AI 实战，观察手感）：

```sh
echo '{"diff":"hard","map":"arena","seconds":12}' > /tmp/ba-ai-cfg.json
ego-browser nodejs < test/ai-vs-human.mjs   # 截屏 /tmp/ba-vs-ai.png + AI 行为与帧率
```

调试参数：`?reset=1` 清存档 · `?auto=1` 机器人自动演示 · `?map=ice|arena|cross|pillars|maze` · `?fps=1` 显示帧率 · `?touch=1` 桌面强制触屏模式。

## 测试

全部用 **ego-lite** 浏览器自动化，当前全绿：

```sh
ego-browser nodejs < test/logic-test.mjs   # 33 项
ego-browser nodejs < test/touch-ego.mjs    # 25 项
ego-browser nodejs < test/mobile-ego.mjs   # 26 项
ego-browser nodejs < test/ai-sim.mjs       # AI 仿真（量化，不是断言式回归）
```

- **逻辑回归 33 项**：自由移动与格内对齐 · 戳泡 · 10 种道具逐一生效（含银针自动脱困、泡泡靴穿泡、钻头穿箱、磁铁吸取、手套举泡投掷）· 道具掉落权重与稀有标记 · 放泡与泡数上限 · 自家水柱不误伤 · 全程零 JS 报错。
- **触屏回归 25 项**：触屏层初始化与对局中激活 · 常驻摇杆底座 · 摇杆 4 向输出与实际位移 · 45° 迟滞 · 快速划动立即换向 · 死区站定 · 放泡键与剩余数角标 · 困泡状态 · 摇杆变向计入自救 · 暂停/恢复 · 触屏下银针自动脱困 · 危机提示能算出引信与可逃方向 · 全程零 JS 报错。
- **手机端回归 26 项**：用 `Emulation.setDeviceMetricsOverride` 模拟 390×844 / 844×390 真机视口——桌面守卫 6 项（不启用增强层 / 不建 UI 层 / HUD 仍留在 stage / 字号原样 / 不生成触摸控件 / 棋盘仍居中缩放）+ 手机布局 13 项（UI 移出 stage、标题 44px、玩家名 11px、计时器 19px、菜单卡贴近屏宽、棋盘顶到上方、炸弹键 96px、常驻摇杆底座、角标、横屏引导…）+ 横屏 4 项（棋盘更大 / 不再提示横屏）+ 引导可关闭并记住。
- **AI 仿真**（`test/ai-sim.mjs`）：全 AI 对局统计死因分布，见上节「AI v2」效果表。24 局 × 4 AI、5 张地图全部 **0% 自炸**；三档难度威胁度 7/12 · 7/12 · 10/12 局（困难档最快 9.2s 打死静止玩家）。

测试环境注意事项：

- ego-browser **不继承 shell 环境变量**，AI 仿真配置必须写进 `/tmp/ba-ai-cfg.json`。
- ego-lite 标签页在后台会被 Chrome 节流，`rAF` 几乎不跑——所有涉及逐帧玩法的断言统一用 `window.__ba.fastForward(sec)` 确定性推进物理，不靠真实帧率。
- ego-lite 无头环境下 `Page.captureScreenshot` 会超时（连标题页都截不出），`ai-vs-human.mjs` 改为直接用 canvas `toDataURL()` 导出 PNG；把渲染 DPR 降到 1.5 后 CDP 截图恢复可用。
- 手机视口用 `page.cdp('Emulation.setDeviceMetricsOverride', { width, height, deviceScaleFactor, mobile })` 模拟，`test/mobile-ego.mjs` 据此断言手机布局。
- 测试跑完必须 `await task.finish({ keep: [] })` 关闭任务空间，否则残留标签页会持续吃内存。
